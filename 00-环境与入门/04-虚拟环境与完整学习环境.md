# 虚拟环境：把这个知识库的库装在一起

关键词：venv .venv 激活 环境隔离 执行策略 安装学习环境

## 为什么需要虚拟环境

一个 Python 安装可以用于很多项目。不同项目可能需要不同版本的包。虚拟环境给每个项目一套独立的包目录；它不是虚拟电脑，也不是必须下载的另一套 Python。

根目录的 `.venv` 保存学习用环境，笔记和例题在其他目录。阅读知识库.html 不需要 `.venv`，运行第三方库例题才需要可用的 Python 和包。

## 最简单的方法

双击根目录「安装学习环境.cmd」。它创建 `.venv` 并安装 requirements.txt，再检查 import。本知识库已经准备本地库安装包，这个入口不联网；适用 Windows 64 位、Python 3.12。完成后双击「运行例题.cmd」即可练习。
如果想学会自己操作，照下面逐步做。

## 方法一：不激活，直接指定解释器（推荐新手）

在 PowerShell 中进入文件夹，执行：

```powershell
Set-Location -LiteralPath 'C:\Users\35107\Desktop\Python知识库'
python -m venv .venv
.\.venv\Scripts\python.exe -m pip --version
.\.venv\Scripts\python.exe -m pip install --no-index --find-links .\15-离线安装包\wheels -r .\15-离线安装包\requirements-离线.txt
.\.venv\Scripts\python.exe tools\check_environment.py
.\.venv\Scripts\python.exe .\03-numpy\数组统计.py
```

第一行进入文件夹；第二行创建环境；第三行确认环境里的 pip；第四行安装包；第五行检查库；最后一行运行例题。
`.\` 表示当前目录，`.venv\Scripts\python.exe` 是环境里的解释器。不激活也能使用它，这种写法不会碰到 PowerShell 激活脚本的执行策略问题。

如果 python 不可用但 py 可用，只把创建环境命令换成 `py -m venv .venv`；后续仍用环境里的完整路径。

## 方法二：激活后使用短命令

PowerShell 激活命令：

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install numpy
python .\03-numpy\数组统计.py
deactivate
```

激活后通常看到 `(.venv)` 前缀。激活只影响当前终端：让 python 优先指向这个环境；`deactivate` 恢复原来的选择。关闭终端不会删除已经安装的库。

CMD 的激活命令与 PowerShell 不同：

```bat
.venv\Scripts\activate.bat
```

如果 PowerShell 提示“不允许运行脚本”，直接使用方法一即可，不需要为了学习修改系统执行策略。

## 检查是不是用对环境

```powershell
.\.venv\Scripts\python.exe -c "import sys; print(sys.executable); print(sys.prefix); print(sys.base_prefix)"
```

环境路径应该指向本文件夹 `.venv`；通常虚拟环境的 prefix 与 base_prefix 不同。仅看到终端窗口标题写 Python，不能证明解释器正确。

## 版本记录与迁移

```powershell
.\.venv\Scripts\python.exe -m pip freeze > requirements-我的环境.txt
```

freeze 记录当前环境里安装的包版本，不会打包包文件，也不能保证跨 Python/操作系统完全复现。换电脑时复制知识库、重新创建 `.venv`、安装要求；不要把 `.venv` 当作可随处复制的安装包。
